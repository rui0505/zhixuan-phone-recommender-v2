# 知选：原 HTML 风格 + Python API 改版设计

日期：2026-10-06

状态：用户已审核确认；等待实施计划与执行方式确认。产品代码、上线配置尚未修改。

设计基线：`51e79b4616a6f27894784d101fbd41a8b73674e7`；隔离分支：`codex/html-api-ui`。

## 1. 目标与范围

用户希望网页更接近原 HTML 界面，同时允许前后端分工开发。本次采用“HTML/CSS/JavaScript 前端 + 独立 Python API 后端”，继续使用已建好的混合数据库、TOPSIS 和可追溯解释；不重做数据库，不改原始数值。

成功标准：用户能在美观、手机端可用的页面上完成需求确认、推荐、目录浏览、配置详情、来源查看、对比和导出；同一条件下的算法结果与当前 Streamlit 版一致。

首版只接入明确的手动条件与权重。原 HTML 的自然语言入口和五题问卷依赖旧接口，不能因为界面上有输入框，就声称已经接入新版需求理解。已有需求抽取模块保留不改，本次不新增聊天接口或启用真实大模型。

本次不包含：登录、个人账户、偏好学习、收藏同步、VIKOR、新数据采集、图片公开发布、数据库写入及正式公网部署。以后需要这些能力时单独设计与授权。

## 2. 架构决策

- 前端复用 `web/static/index.html` 的视觉语言，改为调用新版 API；采用原生 HTML/CSS/JavaScript，不额外迁移 React/Vue。
- 后端沿用项目已有的 Starlette + Uvicorn 技术，建立独立 API 入口，直接声明和锁定所需依赖，不依赖 Streamlit 的间接安装结果。
- 前后端“代码和职责分离、首版同域运行”：一个 Python 服务提供静态页面和 `/api/v1/` 接口。本地只需启动一个服务，减少跨域和双端口配置；将来可在不改算法的情况下拆分部署。
- 新入口与 `app.py` 并存。现有 Streamlit 网站、默认分支和数据发布文件保持不动，作为回退入口。
- 原 `web/server.py` 使用旧 `data/phones.xlsx` 和旧响应结构，保留为参考，不直接作为新 API，也不在后台偷偷回退到旧数据。

```text
浏览器：需求确认 / 手机目录 / 卡片详情 / 配置对比
                         ↓ /api/v1/
Python API：校验请求、校验数据发布版本、统一响应
                         ↓
CatalogRepository → build_input → rank_decision_input
                         ↓
            build_evidence → 模板解释 / 文件导出
                         ↓
           结果 + 来源 + 数据版本 + 决策指纹
```

目录和详情直接读取 Repository，不必执行推荐。前端只负责呈现和交互，不计算第二套 TOPSIS 分数。

## 3. 页面与视觉

参考源是 `web/static/index.html`，不是重新想象一套界面。保留深绿色 `#394c46`、米白背景 `#f4f3ef`、浅色卡片 `#fffefa`、圆角、顶部导航、醒目的标题区和卡片网格。

首版导航为“智能选机 / 手机库 / 对比”。首页标题区下方是可展开的需求面板：新机或二手范围、预算上下限、包含/排除品牌、最低存储、七项权重、目标屏幕尺寸。用户检查后勾选确认，再生成推荐。试验默认权重继续明确标注，不包装为学习所得偏好。

推荐卡片显示：型号、版本、内存/存储、价格及成色、价格记录日期、TOPSIS 相对贴近度、推荐理由、来源入口。每张卡片可展开准确 SKU 的详情并加入对比，最多四个配置。拍照、游戏等缺失或不可比项明确提示，不显示虚构“拍照优秀”“游戏满分”等标签。

TOPSIS 分数是当前候选集和权重下的相对排序分，不称为手机绝对质量分，也不与不同筛选条件下的分数直接比较。

手机库提供搜索、筛选、分页和配置详情；推荐按全部合格候选计算后再分页，不能只对当前页面的手机排名。对比以 `sku_id` 为单位，避免同名不同容量或卫星版串数据。

图片尚未确认公开使用依据：本次不发布原图或网页副本。使用品牌文字、通用图标和“暂无可公开展示图片”提示；原 HTML 的 CSS 概念手机不得标成某型号实物图。

数据状态集中到简洁状态条与详情面板，减少重复大段提示；但影响决策的“无候选 / 数据不足 / 数据发布无效”以及总体验收待完成状态必须显著可见，不能为了美观隐藏。

响应式验收宽度为约 1440、900、390 像素：小屏单列卡片、需求面板可折叠、对比可局部横向滚动；整页不得横向溢出。采用真实按钮、表单标签、键盘焦点和可读颜色，不留不可工作的假控件。

## 4. 模块边界

| 模块 | 责任与依赖 |
| --- | --- |
| `frontend/` | 页面、样式、交互、请求状态；不含私钥和算法副本 |
| `api/app.py` 与 API 路由/契约模块 | ASGI 入口、静态资源、请求校验、响应编码、错误映射 |
| 共享发布校验模块 | 数据库/manifest 哈希、完整性、外键和版本校验；不依赖 Streamlit |
| 共享目录详情模块 | 准确 SKU 详情、作用域过滤、安全来源链接；不依赖 Streamlit |
| 推荐服务模块 | 调用现有 adapter、engine、evidence、export；每次请求独立处理 |
| `catalog/`、`engine.py` | 沿用现有读库、可比性规则、TOPSIS 和证据绑定 |
| `app.py`、`ui/` | 继续服务 Streamlit；仅必要的纯函数抽取和兼容调用调整 |

目前 `ui/catalog_views.py` 导入 Streamlit，后端不能整体引用。将发布校验、SKU 详情、安全链接等纯逻辑抽到共享模块，再由两个入口复用；不把 Streamlit 缓存或会话状态带入 API。现有 `ui/export_results.py` 是可复用的纯导出逻辑，不重写导出规则。

## 5. API 契约

| 方法与路径 | 输入与输出 |
| --- | --- |
| `GET /api/v1/meta` | 发布版本/哈希、统计、品牌、指标白名单、默认权重、功能边界与验收状态 |
| `GET /api/v1/catalog` | 成色、预算、品牌、存储、搜索与分页；返回准确配置和总数，默认 24 条、上限 100 条 |
| `GET /api/v1/skus/{sku_id}` | 返回该 SKU 的机型/版本/配置规格、价格、关联评测及安全来源；不存在返回 404 |
| `POST /api/v1/compare` | 一至四个不重复的 `sku_id`；返回按准确作用域关联的对比字段与来源，不另算综合分 |
| `POST /api/v1/recommend` | 已确认的规范需求、权重、目标、成色和预期发布版本；返回状态、排名/未评分候选、覆盖率、证据和指纹 |
| `POST /api/v1/export/{format}` | 同一确认请求与客户端保存的决策/排名指纹；后端重新计算核对后导出 csv/xlsx/json，不接收客户端成绩作为事实 |
| `GET /healthz` | 服务进程存活，不代表数据库已验证 |
| `GET /readyz` | 发布数据可读取且校验通过；发布无效为 503，不伪装就绪 |

推荐请求统一包含：

- `needs.budget.min/max`：未启用为 `null`，启用为有限非负数，最小值不得大于最大值。
- `needs.min_storage`：不筛选为 `null`，启用为有限正数，单位 GB。
- `needs.brands.include/exclude`：字符串列表；仅允许已知品牌或既有审核过的别名，同品牌不能同时包含和排除。
- `weights`：仅允许现有七项规范指标 `price_cny`、`weight_g`、`storage_gb`、`refresh_rate_hz`、`screen_size_inch`、`dxomark_photo`、`honor_of_kings_avg_fps`；值为 0–10 的有限数，至少一项大于 0。前端显示名称可不同，但不得重复计权。
- `target_screen`：屏幕指标有正权重时必填，范围 3–10 英寸；当前算法按距目标的绝对偏差转换，不改成屏幕越大越好。
- `mode`：仅 `new`、`used`、`all`；`all` 明确包含成色未知，不能把 unknown 默认称为新机。
- `confirmed`：必须为 `true`，仅代表页面确认流程，不作为身份认证或数据库事实。
- `expected_release`：`meta` 返回的数据版本、规则版本、数据库及 manifest 指纹；不一致返回 409，要求刷新并重新确认。

拒绝未知字段、未知指标、字符串冒充数值、布尔值冒充数值、NaN/Infinity、非法分页和重复 ID。JSON 请求体上限 32 KiB；缺字段或非法内容返回明确的 400/422 错误，不静默忽略并扩大候选范围。

响应使用稳定字段：`status`、`reason`、`ranked`、`unscored`、`backups`、`coverage`、`selection_rules`、`effective_weights`、`target_screen`、发布版本与指纹、证据与来源。可评分时完整结果先计算并绑定证据，再由 API 控制展示条数；不可评分时 `ranked` 为空、排名解释证据为 `null`，未评分候选仍保留缺失及来源信息。缺失数值使用 JSON `null`，不填 0、不推算。

非法条件属于请求错误；合法条件产生空候选或可比数据不足属于业务状态，返回 200 并清楚解释。内部错误不返回堆栈、服务器绝对路径或秘密。客户端不能通过 URL 或 JSON 指定数据库路径、SQL、任意文件、模型调用地址。

## 6. 数据与算法保持不变

基线发布为 `catalog-2026-10-06-v2.1`，规则 `rules-2.3.0`，TOPSIS `topsis-1.0.0`；147 机型、150 版本、484 配置。数据库 SHA-256 为 `128207745f5450c285cb8d6c61ff2c692f19387f2df0823690cd5b323c453bc8`。

机器验收 PASS，不等于人工全部确认：整体 PENDING、WPS NOT_CHECKED、人工抽查 0/20 的事实继续显示。本次不把这些状态改成“全部验收通过”。

成色 new/used/unknown 和价格快照分别保留。显示记录来源及日期，不声称价格实时、库存实时；不从“停售”推断渠道库存。关联只使用已有 `model_id / variant_id / sku_id / price_id / run_id / source_id`，不按行号、模糊型号名或内存近似合并。

拍照仍使用来源明确、测试协议可比较的 DXOMARK 照片子分，不把像素数量当拍照能力分。游戏仍使用相同测试条件组的王者荣耀实测平均帧率；协议/条件不足时保留未评分候选并说明，不能拿刷新率或处理器名称替代帧率。

推荐继续使用既有完整可比输入策略与至少两个不同机型的有效候选要求；单一机型多个容量不能制造“比较充分”的假象。候选不足时不输出冠军、不模拟分数、不暗中换权重。

不得修改源 Excel、SQLite 内容或派生规则来配合页面显示；本次不读取后来找到的两份额外 CSV。图片、原始工作簿、输入登记、完整评测摘录、私人路径和密钥不进入新增前端产物。

## 7. 状态一致性与安全

服务启动以及使用数据的请求必须确认当前数据库和 manifest 相互匹配、发布机器验收状态、SQLite 完整性/外键与版本。缓存由两个文件的哈希共同标识；文件变化或校验失败不得继续提供旧成绩。数据库仅只读打开，不在请求中自动重建。

修改条件、权重或发布版本后清除旧结果与旧确认状态。前端使用请求序号或 AbortController 防止较早响应覆盖较新条件；具有清晰的加载、失败、空结果和数据不足状态。后端不以全局变量保存所有人的偏好/结果；浏览器首版只保留当前页面内存中的非敏感状态。

生成成绩时使用实际决策输入和排名指纹，解释证据必须绑定相同 SKU、版本、权重和目标。首版成绩导出仅接受 `ready` 结果，未就绪或指纹不符返回 409，不制造空排名的推荐报告。导出从后端重新计算；CSV 的 UTF-8 BOM、公式注入防护、XLSX 文本 ID 和缺失编码继续沿用既有规范。

原始数据文本使用 `textContent` 或可靠转义，不作为可信 HTML 插入；所有来源链接只允许安全 HTTP/HTTPS，拒绝凭据、脚本协议和控制字符，外链隔离 opener。默认同域，不开放任意 CORS。真实 LLM 默认关闭，秘密不进入 HTML/JS/接口响应。

首版无外部可写操作。公网高并发、账户隔离和平台级限流是正式部署评审内容，不能因为本地 API 可用就声称已经满足生产级容量。

## 8. 验收标准

基线记录中的应用 576 项和管线 37 项测试通过，是旧版本的验证记录，不能直接充当此次改版已通过的证据。实施后必须重新运行相应回归，保留实际命令与结果。

新增验收至少覆盖：

1. 纯服务层和 API 契约：合法请求、数值边界、品牌别名、未知字段/ID、重复计权、请求体限制、分页和比较上限。
2. 数据与作用域：SKU 规格不串配置，卫星版不串普通版，价格成色不误归，发布校验失败不回退旧 Excel。
3. 算法一致性：固定同一数据/条件，与 Streamlit 所用共享核心逐项核对全部候选、排名 ID、原始分数、备选、目标、权重及决策/排名指纹；展示四舍五入不影响原始比较。
4. 错误和边界：无候选、全零权重、单一有效机型、缺失、不同行为测试协议、拍照/游戏不足、发布变化、服务异常均不生成虚假成绩。
5. 安全：恶意文本不能执行、来源协议安全、不泄漏秘密/私人路径、SQL/文件路径不能注入、JSON 无 NaN/Infinity，两个浏览器需求互不污染。
6. 真实浏览器流程：确认需求→推荐→展开来源→加入对比→切换条件清空旧结果→导出；下载后独立核对 CSV/XLSX/JSON 与服务端结果、中文、NULL 和公式转义。
7. 视觉：对照原 HTML 的颜色、导航、标题、卡片和间距，在桌面/平板/手机宽度检查布局、键盘操作、加载和错误提示；不能仅凭编译成功判定界面好看或可用。
8. 不影响已有入口：Streamlit 回归通过；数据库/manifest 哈希保持基线一致；不覆盖旧站数据或已部署分支。

## 9. 协作、发布与回退边界

继续在现有私有 GitHub 仓库的独立功能分支协作，不因 UI 改版再建一个仓库。前端负责交互与契约消费，后端负责接口与证据绑定，数据负责人维护后续数据发布；通过评审 PR 合并，禁止队员直接覆盖已部署主线。

第一阶段交付是本地可运行的新版 HTML/API、验证记录与启动说明。当前设计完成后先由用户审阅，再写实施计划并确认执行方式；本文不是代码已完成或已上线的声明。

用户此前偏好免费部署，本方案沿用“先评估免费方案”的方向，但不承诺永久免费、国内访问稳定或持续在线。原 Streamlit Community Cloud 地址不是这个独立 ASGI 服务的部署入口。

正式公网发布作为后续独立步骤：用户确认平台、账户、仓库可见性、费用/免费限制和数据公开范围后，才配置托管服务、部署及切换访问链接；不购买服务器、不创建外部托管项目、不将私有仓库改为公开、不替换现有网站。

未来上线验收需从匿名浏览器实际打开新地址，完成推荐/对比/导出，并通过可信部署环境提供实际运行 commit 标识；远端仓库 HEAD、提交成功或 CI 通过不能单独证明线上运行的是对应版本。保留原 Streamlit 站作为回退，直至新版验收通过并获得切换确认。
