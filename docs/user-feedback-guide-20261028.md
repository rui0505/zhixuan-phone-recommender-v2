# 知选使用反馈：查看、审核和保存

## 用户入口

打开本地 http://127.0.0.1:8617/ ，选择“数据说明/反馈”，在原数据说明下面继续向下滚动。

- 填写昵称（选填，不填为匿名用户）、体验评分、反馈类型、涉及页面和5–2000字正文。
- 提交后显示反馈编号，状态为待审核。失败时表单保留，重试不会重复入库。
- 管理员审核通过后，下方“大家的使用反馈”中才会公开昵称、评分、正文、类型及时间。
- 已公开的评论可撤回；评分均值和条数只计算当前公开评论。
- 这是知选网站的使用体验反馈；手机详情中的淘宝买家评价保持原有独立数据来源。

## 我在哪里看全部反馈

本地预览运行时，双击项目根目录 **打开反馈管理.cmd**。它会把管理密钥复制到剪贴板并打开 http://127.0.0.1:8617/feedback-admin.html 。粘贴密钥，点击“查看反馈”。也可以从评论区最下方的“反馈管理”进入。

管理页默认显示待审核，支持切换已发布、未通过或全部反馈，20条分页。

- **通过并发布**：立即进入公开列表。
- **不予公开**：保存为未通过，普通用户看不到。
- **退回待审核**：撤回已公开评论，重新进入审核队列。
- **导出全部 CSV**：包含所有状态、评论内容、评分、创建和审核时间；UTF-8 BOM，中文可用Excel打开，正文中的公式起始字符已转义。
- **退出管理**：清空当前页面中的密钥、私有列表和统计。刷新也需重新输入。

密钥不会出现在网址、前端代码或本次文档中。远程管理必须用HTTPS，本机127.0.0.1/localhost预览可用HTTP。本次只实现本地，没有改动公网服务或真实用户数据。

## 数据实际存在哪里

| 环境 | 评论数据库 | 管理密钥 |
| --- | --- | --- |
| 当前本机 | 项目根目录 `local_state/feedback.sqlite3` | `local_state/feedback-admin.key` |
| 按本次systemd配置部署后 | `/var/lib/zhixuan/feedback.sqlite3` | `/var/lib/zhixuan/feedback-admin.key` |

应用首次读取/提交反馈时自动创建。通过服务端环境变量 `PHONE_FEEDBACK_DB` 可以指定绝对数据库路径。管理密钥默认随机生成，也可由服务端 `PHONE_FEEDBACK_ADMIN_TOKEN` 覆盖（至少32字符）。本机使用覆盖值时需在同样环境下运行管理工具。

数据库主要字段：编号、昵称、1–5星评分、反馈类型、涉及页面、正文、审核状态、提交时间、更新时间、发布时间。另存去标识化限频桶，用于每网络来源每小时最多10条的提交限制；不保存原始IP，也不自动收集联系方式、用户购机需求或大模型输入。

评论先落入服务器数据库，再返回成功回执。关闭浏览器或重启服务后数据仍在。发布代码时保留这个目录，反馈与手机的只读 `data/catalog.sqlite`、离线 `buyer_reviews.json` 分离。

`local_state/` 已加入Git忽略；发布包仅包含代码和配置，不含评论数据库、管理密钥或备份。现有服务器升级时必须同步应用新的systemd状态目录配置并重新加载服务，不能只替换前端文件。

## 备份

本机在项目根目录的PowerShell执行，目标文件须尚未存在：

```powershell
.\.venv\Scripts\python.exe scripts/feedback_admin.py --backup local_state/backups/feedback-20261028.sqlite3
```

工具使用SQLite backup API得到一致性数据库快照，包含待审核、已发布和未通过评论。可在服务运行期间备份，不直接复制正在写入的数据库。重复备份请换新文件名；实际备份文件不会上传Git。本次提供手动工具，尚未设置定时备份。

生产服务器在应用虚拟环境中运行同一脚本，指定 `--db /var/lib/zhixuan/feedback.sqlite3` 及独立备份输出路径。管理密钥文件另行保存到私有备份位置。

恢复时先停止反馈服务，将备份恢复到配置的数据库路径，确认服务账户拥有读写权限后启动服务。使用原密钥文件可保持原管理入口；未保留密钥时，应用可生成新的管理密钥。
