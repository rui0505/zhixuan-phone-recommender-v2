# 需求抽取独立核验与异常确认

用户已选择并授权实施“大模型＋针对性规则核验＋异常确认”。目标是在现有 HTML/API 链路中发现明显错误，保留可解释的修正记录，阻止未核对异常直接生成推荐。

采用独立的纯 Python 核验模块，在模型归一化、契约整形之后、生成网页草稿之前运行。规则只识别明确的预算边界、品牌包含/排除、存储门槛、尺寸与七维强度；无匹配不是模型出错的证明。可独立确定的值可填入待确认草稿，同时展示原模型值、规则建议与原文。无证据的硬条件清空并要求确认；复杂或矛盾表达保留为异常，不冒充已经理解。

网页逐项显示异常，用户核对并勾选后，还需原有整体确认才能推荐。修改条件使异常勾选失效；新一轮抽取替换异常清单。模型失败保留手动入口、撤销旧推荐确认。规则没有发现异常时只称“未发现已覆盖类型的冲突”，不称“无幻觉”。

不训练第二个模型，不引入额外依赖，不改评分数据或默认权重，不增加付费调用。本轮在现有干净工作副本的新个人分支本地实现，部署与推送另按授权执行。旧 Streamlit/实验入口不改变；生产 HTML/API 统一应用核验。

备选完整 BERT/CRF 双路抽取需要标注、训练和裁决；AISM 用于因素结构，不适合承担此处原文核验。选用规则方案以控制一天内的实现与验收范围。

验收：注入错误模型报文测试预算错值、虚构条件、否定反转、阈值当偏好、多轮修改与原文矛盾；通过真实 API 验证草稿；执行真实前端处理器测试与本地浏览器桌面/窄屏检查；全量回归和发布包独立导入。离线夹具验证机制，不等于真实模型准确率评测。
