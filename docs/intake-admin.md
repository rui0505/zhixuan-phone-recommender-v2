# 机型录入与评论审核管理

这是 `rui0505/zhixuan-phone-recommender-v2` 的管理功能，不能复制到旧 `phone-demo`。交接包的表单结构和校验规则已经整合；没有执行会覆盖原API的安装脚本。

## 进入管理

- 本机服务运行时，双击项目根目录 `打开机型管理.cmd`。工具复制维护密钥并打开 `http://127.0.0.1:8617/admin.html`；粘贴后点击“进入机型管理”。
- 评论审核在 `/feedback-admin.html`，与机型管理共用同一维护密钥；两个页面有互相跳转入口。页面间不通过URL传递密钥，刷新或切换后需重新粘贴。
- 云端部署完成后使用 `https://zhixuanji.cn/admin.html`。远程HTTP页面禁止输入密钥，API也拒绝非HTTPS远程管理。
- 若已将服务器私有维护密钥下载到 `local_state/cloud/feedback-admin.key`，双击 `打开云端后台.cmd` 可复制云端密钥并打开云端后台；本机密钥与云端密钥独立。

## 添加新机型

1. 填品牌、完整机型名称、发布时间、版本及地区。先核对手机库是否已有同机型；当前支持新增机型，已有机型补配置或改规格需要后续独立的修订流程。
2. 添加准确的内存/存储配置，可一机多配置。每个配置填价格、价格口径、新机/二手/未知成色、记录日期和出处链接。
3. 填有出处的技术规格。机型与规格来源链接和每个配置的价格来源分别保存。数字未知留空；文本相机、处理器等保留原文，不用博主推荐名次或不存在的评测成绩补数值。
4. **保存草稿**允许先缺少价格/日期/出处；同一草稿可加载、继续编辑，不会每次生成重复记录。**提交待审核**要求必要信息完整。
5. 加载待审核记录，打开保存的来源链接进行核对。勾选来源确认后点击**确认发布到手机库**。未保存的改动会撤销来源确认，必须先保存再复核。
6. 发布成功后手机库版本更新；已经打开的同源网站通过广播刷新，恢复焦点时也检查更新，无需改前端代码或重启服务器。此前确认的推荐因数据版本变化失效，需要用户重新确认。

没有资料的参数显示“资料未记载”；没有图片的新机型显示占位，当前未提供图片上传。只具备基础配置的机型可以展示在手机库，但是否能进入推荐仍受原有指标完整性、可比性和默认权重规则约束。

已发布记录保持只读。重复点击发布不会重复添加。多人同时维护时以记录修订号和手机库版本校验，冲突后重新加载记录、核对来源再发布。若发布切换成功而回执丢失，下一次读取会根据已发布内容恢复状态，防止把实际已发布机型改成草稿或拒绝。

## 存储和发布

| 内容 | 本机默认 | 云端持久目录 |
| --- | --- | --- |
| 评论 | `local_state/feedback.sqlite3` | `/var/lib/zhixuan/feedback.sqlite3` |
| 录入草稿/审核记录 | `local_state/intake.sqlite3` | `/var/lib/zhixuan/intake.sqlite3` |
| 共用维护密钥 | `local_state/feedback-admin.key` | `/var/lib/zhixuan/feedback-admin.key` |
| 已发布机型及历史快照 | `local_state/catalog/` | `/var/lib/zhixuan/catalog/` |

`PHONE_FEEDBACK_DB`决定评论数据库位置，录入数据库放在同目录。`PHONE_CATALOG_STATE`可覆盖活动目录位置；默认在评论数据库旁的`catalog/`。可选`PHONE_ADMIN_TOKEN`仅兼容旧`X-Intake-Token`调用，默认管理页使用共用的随机Bearer维护密钥。

每次发布从当前验证通过的目录建立新SQLite快照，只追加审核通过的数据，原始`data/catalog.sqlite`不改。规格、价格、来源保留关联；原有图片和买家评价与新目录重新绑定指纹，不能把不同版本的资料混用。新快照验证通过后，原子切换`catalog/current.json`；失败保留上一版本。

代码重新部署时保留整个持久目录。若新代码包的基础手机数据指纹改变，活动指针会拒绝自动混用，须先制定数据迁移；不能用空目录覆盖管理员已发布数据。

## 查看、导出及备份

机型队列提供分页、加载编辑、拒绝和全部JSON导出；评论管理保留审核、撤回和全部CSV导出。没有账号系统时，共用密钥代表项目维护权限，应仅在自己的管理环境使用。

SQLite一致性备份示例（目标文件须尚不存在）：

```powershell
.\.venv\Scripts\python.exe scripts/feedback_admin.py --backup local_state/backups/feedback-20261028.sqlite3
.\.venv\Scripts\python.exe scripts/feedback_admin.py --db local_state/intake.sqlite3 --backup local_state/backups/intake-20261028.sqlite3
```

还需备份共用密钥和整个`catalog/`（指针、快照、共享媒体）。复制整个状态目录前暂时停止服务，可得到同一时刻的完整备份；仅有队列JSON导出不等于完整目录备份。本次未配置定时备份或历史快照自动清理，旧快照保留便于人工恢复。
