## 结构依据与边界

当前项目没有专家给定的 AISM 关系矩阵。第一版以现有七维定义和 `catalog/spec_reference.py:reference_values` 的真实计算依赖为初始模型：处理器→游戏参考分，电池容量→游戏参考分。两条边分别对应既有 .8/.2 系数，AISM 本身只使用二元邻接关系；这不是用户偏好因果图，也不是领域专家调查结果。其他维度保持独立，不虚构物理因果或偏好传播。

版本化 JSON 记录节点定义、边的语义、来源与适用范围。纯 Python 从邻接矩阵计算带自反关系的可达矩阵，再通过 R(i)=R(i)∩Q(i) 提取结果优先 UP 层级、Q(i)=R(i)∩Q(i) 提取原因优先 DOWN 层级，循环节点作为强连通组处理。对缩点后的 DAG 去掉传递边，提供可审查的结构骨架。UP/DOWN 的第一层分别是结果端/原因端，不代表偏好强度。

方法参考：[WINGS-AISM 原始研究](https://doi.org/10.1016/j.net.2024.08.034)、[AISM 层级提取研究](https://www.tandfonline.com/doi/full/10.1080/13467581.2025.2497406)。这些研究支持算法步骤，不是本项目两条边的外部实验证明。

## 接入方式

计算得到的层级、节点定义和关系边界写入统一 SYSTEM_PROMPT，普通模型适配器与正式 API 共用。模型仍只输出既有七维五档判断、参数与原话证据。AISM 不重写模型值，不因用户重视游戏而自动提高处理器或电池的用户权重，也不对幻觉作出“通过/拒绝”判断。

结构模型和算法版本及内容摘要绑定到提示词版本；API 元数据、抽取结果附相同结构摘要。修改配置需重启进程以使用一致的新快照。网页新增折叠的“查看维度关系（AISM）”，展示初始模型来源、关系及 UP/DOWN 分层；不再增加异常逐项勾选。

## 验收

先用手算链、分叉、孤立点、强连通循环检查闭包/双向分层/骨架，再核对两类真实适配器发出的请求确实带有计算结构；验证结构版本可追溯、游戏需求不会传播成其他维度权重。执行 HTTP、网页整体确认/推荐、全量回归与独立发布包验证。离线夹具只证明链路；不宣称真实模型语义准确率或幻觉率已改善。保留本地演示，不自动推送或发布。
