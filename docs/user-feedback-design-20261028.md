# 数据说明 / 反馈

用户明确选择公开评论、审核后发布，并要求入口位于现有数据说明页，导航名改为“数据说明/反馈”。在原数据说明内容下方继续滚动进入反馈区，沿用知选现有蓝白界面，参考所给4399截图的“编辑器 + 发表须知 + 已发布评论”结构，不复制品牌和游戏内容。

评论支持可选昵称（默认匿名用户）、1–5星体验评分、反馈类型、涉及页面及5–2000字正文。评论提交后进入 pending；只有管理员审核为 published 才能被公开列表查询，rejected 与 pending 均不公开。用户获得反馈编号，失败保留输入，再试复用提交编号以防重复入库。公开统计仅计算已发布评论，不伪造评论或评分。当前不增加账号、图片上传、点赞、回复或通知。

后端独立 FeedbackStore，使用 SQLite 事务和分页，不写入只读手机 catalog.sqlite。开发默认 local_state/feedback.sqlite3，部署由 PHONE_FEEDBACK_DB 指定 /var/lib/zhixuan/feedback.sqlite3；systemd StateDirectory 保持独立于代码发布。数据库保存评论、审核状态和时间、必要的去标识化限频桶；不保存原始IP、联系方式、购机需求或模型上下文。正文和昵称按纯文本渲染。请求严格验证字段，公共提交每网络来源每小时10条，限频跨重启有效。重复提交同一编号内容相同则返回原回执，不同内容返回冲突。反馈接口独立于手机目录可用性。

GET /api/v1/feedback 返回仅公开字段的 published 列表（20条分页）及公开评分统计；POST 同路径提交。管理员在 /feedback-admin.html 输入管理密钥，密钥仅保留当前页面内存，通过 Authorization Bearer 调用 /api/v1/admin/feedback（列表）、/{id}（PATCH审核）、/export（CSV全量导出）。管理密钥由服务器首次使用时随机生成，保存在数据库旁 feedback-admin.key，环境 PHONE_FEEDBACK_ADMIN_TOKEN 可覆盖；不进入前端、Git或部署包。未鉴权不能读取待审正文、统计或导出；CSV对公式注入转义。客户端请求超时后可重试，管理员退出清空私有内容与密钥。

服务端数据库和管理密钥均需备份；提供随现有应用运行环境使用的CLI，执行 SQLite backup API 的一致性备份。发布包含新代码与配置，不含实际反馈或密钥。远程管理必须通过HTTPS，只有本机回环预览允许HTTP；前后端均限制，反向代理传递实际协议及来源。现有公网不在本次授权范围内自动更新；本地提交、审核、公开、撤回、备份恢复和桌面/手机布局均需验证后交付。
