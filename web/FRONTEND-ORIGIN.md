# `web/static/index.html` 的来源与改造

## 来源

`web/static/index.html` 基于一份静态原型（`zhixuan-phone-web.zip` 里的
`index.html`）改造而来。原型的视觉语言（配色变量、卡片结构、响应式断点、
`light-dark()` 主题适配）保留了下来，**数据与交互全部换掉了**。

原压缩包里的 `preview.html` 只是把 `index.html` 塞进 iframe 的导出包装，
没有独立内容，已丢弃。

## 改掉了什么，为什么

| 原型 | 现在 | 原因 |
|---|---|---|
| 9 款虚构机型硬编码在 JS 里 | `/api/phones` 取真实 46 款 / 156 条配置 | 虚构机型与真实数据表无关，用户点进去对不上 |
| `p-recommend` 用关键词正则冒充「AI 推荐」 | `POST /api/recommend` 走真实管线 | 正则只认「四位或五位数字 + 拍照/游戏/折叠」，不是需求理解 |
| 卡片上的「拍照 / 游戏 / 续航」三级评价（优先/均衡/基础） | 删除 | **数据表里没有电池容量、没有折叠形态、没有画质指标**，这三个评价没有任何依据 |
| 分类「影像摄影 / 游戏性能 / 长续航 / 折叠大屏 / 商务办公 / 均衡全能」 | 「小屏 / 大屏 / 轻薄 / 高刷 / 大存储」+「按预算」「按品牌」 | 同上：分类必须由数据表里真实存在的列推导 |
| 人群分类（在校学生 / 职场通勤 / 给父母买…） | 删除，换成按品牌 | 人群与配置参数之间没有可验证的映射，属于主观贴标签 |
| 「优势 / 取舍」两句手写文案 | 引擎给出的「比预算上限低 N 元」等真实参数差异 | 手写文案是编造的 |
| 页脚「9款虚构机型…未接入真实推荐模型」 | 真实数据规模 + 算法说明 + 数据边界 | 自述必须与实现一致 |

## 保留了什么

导航（智能选机 / 手机库 / 对比）、价格排序与「查看更多」、卡片展开分析、
最多三款对比、响应式布局、浅色/深色自动适配、CDN 图标失败时的降级。

## 密钥

前端**不接触任何密钥**。它只把一句中文发给同源的 `/api/recommend`，
模型调用全部发生在服务端。
